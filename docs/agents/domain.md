# Domain docs

This repository uses a single domain context.

Before exploring or changing established behavior, read `CONTEXT.md` when it exists and the relevant ADRs under `docs/adr/`. Proceed silently when either location does not yet exist; domain-modeling work creates them when terminology or decisions need a durable home.

Use the glossary's terms in specifications, issue titles, tests, and code. Surface any conflict with an existing ADR instead of silently overriding it.
